## 现状快照（v1）

- 能力：本地转发（-L）/ 反向转发（-R）/ 动态 SOCKS（-D），一键启停、
  后台常驻（detached spawn，退出 uTools 隧道不断）、状态机可视、
  每隧道独立日志、自动重连（进程在场时）、adopt 接管、JSON 导入导出（不含密码）。
- 安全定位：密码 / passphrase 存 `utools.dbCryptoStorage`，秘密只经内存进子进程 stdin，
  不导出、不云同步。
- 平台：macOS 为主；`engine/platform.js` 已为 Windows/Linux 预留接口。

### v1 已知限制（演进的主要输入）

1. macOS 为主；Windows/Linux 代码预留未验证。
2. 被接管的常驻隧道无实时日志管道（历史日志仍可读）。
3. 自动重连仅在插件进程在场时生效（uTools 完全退出期间断开需重开后手动/接管）。
4. 反向转发服务器侧仅绑定 127.0.0.1（安全默认，无开关）。

## 演进主线

### 主线一：补 v1 已知限制（可靠性，建议优先）

| 演进项 | 方案要点 | 难度 |
|---|---|---|
| 常驻隧道实时日志 | 接管后可用 `log stream --predicate 'processID == …'` 或 stderr 重定向文件定期采样，近似补上实时管道 | 中 |
| 离线断线自愈 | spawn 时包一层轻量 shell 守护循环（`while true; do ssh …; sleep N; done` + 指数退避），守护逻辑随 detached 进程常驻，不依赖插件存活；需处理与状态机/adopt 的一致性 | 中高 |
| 反向转发绑定开关 | 增加「允许远端局域网访问」选项（配合 `GatewayPorts` / `0.0.0.0` 绑定），UI 带风险提示 | 低 |
| Windows/Linux 落地 | 主要工作：agent 解析链、setsid/密码写入替代、路径差异；建议先 Windows（OpenSSH 内置）；若上架市场则为门槛项 | 高 |

### 主线二：配置与效率（README v2 备选展开）

- **`~/.ssh/config` 导入**（建议 v2 主打）：解析 Host 条目批量生成隧道草稿，
  ProxyJump / IdentityFile / Port 直接映射现有数据模型；
  进阶：增量同步（config 变更后提示更新）。
- **隧道分组 + 一键场景**：如「开发环境」组一键启动多条隧道；
  配合 uTools 动态指令 `启动 <组名>`。
- **快速复制**：卡片一键复制转发地址（`localhost:18080`）、生成 curl / 浏览器打开命令、
  SOCKS 复制代理配置串。
- **模板 / 克隆隧道**：常连同一批机器时减少重复填写。

### 主线三：可观测与运维增值

- **连接历史**：启停、断线、错误时间线（回答「昨晚隧道为什么断了」）。
- **流量统计**：`nettop -p <pid>` 低频采样，卡片显示实时速率 + 累计流量。
- **日志全文检索**：日志已在 `~/.utools-ssh-tunnel/logs/`，加跨隧道搜索面板，纯前端工作量小。
- **健康探活升级**：从「仅启动时探活」（`engine/ports.js`）扩展为运行期周期性探活，
  端口失联主动标黄 / 触发重连，而非等 ssh 超时。
- **状态轻量触达**：uTools 插件无法做原生 menubar；以系统通知 +
  搜索框指令查状态作为轻量路径。

### 主线四：平台化与生态（远期，可选）

- **上架插件市场**：前置条件为 Windows 兼容、密钥文件路径校验、隐私声明
  （「密码不出本机」是卖点）。
- **uTools 能力联动**：超级面板选中 IP 时提供「为此主机建隧道」；
  sftp/scp 快捷入口（用户心智相近，但超出隧道定位，需单独论证）。
- **多机同步替代方案**：不做云同步；支持导出到指定目录（iCloud/Dropbox 路径）
  实现手动多机同步，密码仍不导出。
